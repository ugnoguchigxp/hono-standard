# 実装計画 07: 段落・見出しのスラッシュメニュー

状態: 未実装

依存: [計画 06](./plate-notion-plan-06-autosave.md) の自動保存が完成し、連続入力・失敗・競合のテストが通っていること。

## ゴール

空の段落の先頭で `/` を入力すると、段落・見出し1・見出し2の3項目だけを選べるメニューを表示する。選択すると現在の段落がその種類に変わり、通常の本文として自動保存される。今回は新しいブロック型を追加しない。

Plate の [Slash Command](https://platejs.org/docs/slash-command) は編集中に `slashInput` という一時ノードを作る。計画 04 の API はこのノードを受け付けない。**メニューを開いている間の一時ノードを保存しないこと**が、この計画で最も重要な条件。

## 振る舞いを固定する

| 操作 | 期待する結果 |
| --- | --- |
| 空の段落の先頭で `/` | メニューが開き、3項目を表示 |
| `/h` と入力 | 見出し1・見出し2に絞り込む |
| `ArrowDown` / `ArrowUp` | 選択項目が移る。入力フォーカスはエディタ内に残る |
| `Enter` または項目クリック | 選択した種類に変換し、メニューを閉じる |
| `Escape` | 変換せずメニューを閉じる。既存の段落本文は失わない |
| 普通の本文中で `/` | 文字として入力でき、メニューは開かない |
| メニューを開いたまま1秒以上待つ | PUT は送られず、保存状態を「保存済み」に変えない |

空の段落以外では起動しない。メニューには今回使えないリスト、画像、AI などを表示しない。選択後はエディタへ戻って続けて入力できる。既存の見出しツールバーも残す。

## 自動保存との境界

メニューが開いている間は、計画 06 の自動保存タイマーを停止し、手動の「保存」ボタンも無効にする。`slashInput` を含む Plate 値を `latestValue` や TanStack Query のキャッシュへ確定済み本文として入れない。メニューを選択・キャンセルした後、Plate が一時ノードを除いた値を出したことを確認してから `onChange` と自動保存を再開する。

値から `slashInput` を検出した場合、送信前の最後の安全策として PUT を実行しない。クライアントで一時ノードを勝手に削除した別の JSON を保存しない。ユーザーの見ている本文と保存する本文を一致させる。もし一時ノードが残り続ける場合は保存を停止して明確なエラーを出し、見えない形で本文を捨てない。

選択・キャンセル後に本文が変更されていなければ新しい保存リクエストは不要。変更された場合だけ計画 06 の1秒待機を開始する。メニュー表示状態は一時的な UI state であり、DB に保存しない。

## 実装順序

1. `git status --short --branch`、`bun run typecheck`、`bun run test` の変更前結果を記録する。計画 06 の保存制御とテストがなければ、仮の保存処理を作らず依存不足を報告する。
2. 計画 03 で固定した Plate のバージョンを確認し、対応する `@platejs/slash-command` を `bun add` する。導入した版の公式 API に従い、`SlashPlugin` と `SlashInputPlugin` を `web/src/components/page-editor.tsx` に登録する。別版のサンプルコードを混ぜない。
3. `web/src/components/page-editor-slash-menu.tsx` に3項目だけのメニューを作る。各項目は既存の段落/H1/H2 変換を呼び、メニューの一時入力を確定本文から除く。キーボードとクリックの両方で選べるようにする。
4. `web/src/hooks/use-page-autosave.ts` に「Plate 値に一時ノードがある間は保存しない」ガードを追加する。`PageEditor` からメニューの開閉とクリーンな本文変更を伝える。既存の単一 PUT、revision、失敗・競合の処理は変えない。
5. `web/src/components/page-editor.test.tsx` と `web/src/hooks/use-page-autosave.test.ts` に下記のテストを追加する。jsdom の選択操作で再現できない場合は既存の Playwright でメニュー操作を検証する。

## 必須テスト

| ケース | 合格条件 |
| --- | --- |
| `/` の起動条件 | 空の段落先頭だけメニューが開く |
| 絞り込み・矢印・Enter | 選んだ見出しになり、本文の JSON は `p/h1/h2` のみ |
| Escape | 元の段落本文が残り、メニューが閉じる |
| 項目クリック | キーボードと同じ変換結果になる |
| 1秒以上メニューを開いたまま | PUT 0件、`slashInput` はキャッシュに入らない |
| 選択後の自動保存 | PUT の値に `slashInput` がなく、サーバーで受理される |
| 他の場所で `/` | 通常の文字入力になり、本文は保存できる |
| 既存の保存テスト | 計画 06 の遅延応答・失敗・競合が引き続き通る |

## 検証と報告

順に `bun run test -- web/src/components/page-editor.test.tsx web/src/hooks/use-page-autosave.test.ts web/src/views/pages-view.test.tsx`、`bun run typecheck`、`bun run lint`、`bun run format:check`、`bun run build:web`、`bun run verify`、`git diff --check` を実行する。すべてエラーなしを合格とする。ブラウザーではメニューを1秒以上開く、選択する、再読み込みする操作を行い、保存結果が一致することを確認する。失敗時は対象箇所を直して対象テストから再実行し、最後に全体ゲートを通す。

完了報告には使用した Plate パッケージのバージョン、実際の一時ノードの形、PUT に送った JSON の検証結果、未確認事項を記載する。

## 非目標

リスト、チェックリスト、引用、画像、ブロックのドラッグ、ページ検索、AI 機能。DB と API のスキーマは変更しない。
