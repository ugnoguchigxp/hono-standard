# 実装計画 08: ページタイトルの編集と保存

状態: 未実装。設計書のみ作成。

依存: [計画 01](./plate-notion-plan-01-pages-api.md) の改名 API、[計画 02](./plate-notion-plan-02-sidebar.md) の一覧・詳細画面、[計画 05](./plate-notion-plan-05-editor-save.md) の本文保存・離脱確認。

## 目的と範囲

ページ詳細画面で「無題」を任意のタイトルへ変更し、保存後に詳細画面とサイドバーへ反映する。再読み込み後も変更したタイトルを復元できるようにする。

根拠は [全体コンセプト](./plate-notion-concept.md) の「ページを開くと、タイトル、アイコン、本文をその場で編集できる」と、段階 1 の「タイトル変更」。計画 01〜07 で未接続になっているタイトル編集を、既存 API を利用して完成させる。

今回はタイトルを明示的に保存する。タイトルの自動保存、アイコン・カバー、ページ移動・複製・削除、追加ブロックは対象外。新しい API、DB 列、migration、依存パッケージは追加しない。

## 画面と操作の契約

1. 通常時はタイトルと「タイトルを編集」ボタンを表示する。
2. 編集開始時に現在のタイトルを入力欄へコピーする。入力欄にはアクセシブルな名前「ページタイトル」を付ける。
3. 「タイトルを保存」で PATCH を送信する。Enter でも保存できるが、日本語入力の変換確定中には送信しない。
4. 「キャンセル」または Escape でタイトルの下書きだけを破棄する。本文は変更しない。
5. 前後空白除去後、元のタイトルと同じなら通信せず編集を終了する。
6. 空白のみ・200文字超は入力エラーを表示し、通信しない。文字数の判定は共有 Zod スキーマに合わせる。
7. 送信中はタイトル入力・保存・キャンセルを無効にし、同じページへの改名リクエストを重複させない。
8. 成功後はサーバー応答のタイトルを表示し、サイドバーにも反映する。
9. 失敗時は入力を残し、エラーと「再試行」を表示する。自動再送しない。404 では「ページが見つかりません」と表示し、成功扱いにしない。
10. 本文とタイトルの保存状態は別々に表示する。本文が保存済みでも、未保存のタイトルがあれば離脱確認を出す。

タイトル下書きはローカル state に置き、入力中の値をサーバー応答キャッシュへ書き込まない。

## モジュールとデータ契約

| 対象 | 変更内容 |
| --- | --- |
| `web/src/api.ts` | `updatePageTitle(pageId, input)` と `useUpdatePageTitleMutation(userId, pageId)` を追加 |
| `web/src/components/page-title-editor.tsx`（新規） | タイトル編集 UI、共有スキーマによる検証、下書き・成功・失敗の管理 |
| `web/src/views/pages-view.tsx` | タイトル編集部品を接続し、タイトルと本文の離脱状態を合算 |
| `web/src/page-edit-guard.tsx` | 現行の `unsaved` / `saving` を利用。複数部品から直接登録せず、ページ画面側で一度だけ登録 |
| `web/src/styles.css` | タイトル入力・状態・エラーの必要最小限の表示 |
| 対象テスト | 改名、キャッシュ反映、失敗、離脱、本文との併用を追加 |

既存 API 契約を使う。

```text
PATCH /api/pages/:id
入力: UpdatePageTitleInput  // { title: string }
成功: UpdatePageResponse    // { page: Page }
失敗: 未ログイン 401、入力不正 400、他人のページ・存在しないページ 404
```

型と入力検証の正本は `shared/schemas/pages.schema.ts`。認可の正本は `api/modules/pages/pages.service.ts` の `renamePage`、HTTP 契約は `api/routes/pages.route.ts`。本文の `revision` はタイトル保存へ流用しない。

タイトル側の状態は、編集モード、下書き、確定タイトル、mutation の送信中・エラーを基本とする。未保存は共有スキーマで正規化した値と確定タイトルから算出し、入力不正の下書きも離脱保護の対象にする。

## キャッシュと本文保存の境界

既存 query key を維持する。

- 一覧: `['pages', userId, 'list']`
- 詳細: `['pages', userId, 'detail', pageId]`

改名成功時は関数形式のキャッシュ更新で、その時点のキャッシュにある対象ページのタイトルだけを更新する。詳細の `content.value` と `content.revision`、一覧の順序・親子関係は保持する。古い詳細スナップショットを丸ごと書き戻さない。存在しない詳細キャッシュを PATCH 応答だけで不完全に生成しない。

その後、対象ユーザーの一覧・対象ページ詳細を invalidate してメタデータを再取得する。再取得結果で編集中の本文やタイトル下書きを上書きしない。保存開始前から進行している GET についても、古いタイトルへ戻ることがないよう対象 query のキャンセルと更新順序を扱う。

タイトル PATCH と本文 PUT は別データを更新するため、並行実行を許容する。双方の応答が逆順でも、タイトル・本文・revision が失われないことをテストする。更新日時は再取得で整合させる。

セッション変更後に届いた旧ユーザーの mutation 応答は、キャッシュを再生成したり新ユーザーの画面へ反映したりしないよう、現在のセッションとの一致を確認する。

## 依存関係と並行実装

計画 06・07 の完成はタイトル編集自体の必須条件ではない。ただし、以下は同じファイルを変更するため、実装前に並行作業の最新状態を読み直し、既存の変更を取り消さない。

| 並行計画 | 重複箇所 | 08 の境界 |
| --- | --- | --- |
| 05・06 | `pages-view.tsx`、離脱確認 | 本文保存制御を維持し、タイトル状態の合算だけを追加 |
| 06 | `api.ts`、詳細キャッシュ | 本文応答は content、タイトル応答は title を更新する |
| 07 | ページ画面の保存制御 | スラッシュメニューの一時ノードと保存停止処理には手を加えない |
| 02 | 一覧表示 | タイトル反映のみ。ツリー構造・展開状態を変更しない |

離脱状態はページ画面で次のようにまとめる。

```ts
unsaved = bodyUnsaved || titleUnsaved;
saving = bodySaving || titleSaving;
```

タイトル部品と本文部品がそれぞれ既存 guard を更新し、互いの状態を消す構造にはしない。本文用の再読み込み確認も、タイトル下書きを巻き込んで破棄しない。本文側のタイマー・保存可否には本文固有の状態を使い、合算した離脱状態を理由に本文の自動保存を止めない。

1. `git status --short --branch` と最新コードから、計画 05〜07 の進行状況を確認する。共通ファイルの担当範囲を合わせ、変更前の対象テスト・型チェックの結果を記録する。

3. `web/src/components/page-title-editor.tsx` と同名の `.test.tsx` を追加する。編集開始、共有スキーマ検証、明示保存、キャンセル、失敗時の下書き保持を実装する。本文の state を持たせない。
4. `web/src/views/pages-view.tsx` のタイトル表示と置き換える。タイトル・本文の状態をページ単位で合算し、ページ切替・ログアウト・再読み込みの既存保護へ接続する。
5. タイトル PATCH と本文 PUT の応答順逆転、GET 再取得、ページ切替、セッション変更を遅延 Promise で検証する。必要な修正を共通ファイルへ限定する。
6. 対象テストから開始し、既存の本文保存・自動保存・スラッシュメニューの回帰確認、全体ゲートへ進む。

## 必須テストと受け入れ基準

| ケース | 合格条件 |
| --- | --- |
| 改名して保存 | PATCH は1件。詳細・サイドバーがサーバー応答のタイトルになる |
| 前後空白 | 共有スキーマで除去したタイトルを送る |
| 空白のみ・200文字超 | エラー表示、PATCH は0件。200文字は受理する |
| 同じタイトル・キャンセル | PATCH は0件、本文下書きは維持 |
| 日本語 IME の Enter | 変換確定で保存されない |
| 通信失敗・404 | 下書きを保持し、成功表示・自動再送をしない |
| タイトルだけ未保存 | ページ切替・ログアウト・再読み込みで離脱保護が働く |
| タイトル保存中 | ページ切替・ログアウトを保護し、重複送信しない |
| 本文 PUT と応答順逆転 | 最新のタイトル・本文・revision がすべて残る |
| 再取得中に入力 | 入力中の下書きが GET 応答で戻らない |
| ユーザー変更後の遅延応答 | 旧ユーザーのキャッシュ・下書きが新セッションに残らない |
| ブラウザー再読み込み | 保存したタイトルと本文、階層が復元される |

対象テストは `web/src/components/page-title-editor.test.tsx`、`web/src/api.test.ts`、`web/src/views/pages-view.test.tsx`、必要に応じて `web/src/page-edit-guard.test.tsx` に置く。遅延応答は Promise で制御し、実時間の sleep を使わない。既存 API の認可テストも回帰対象に含める。

## リスク・未決事項

- 既存のタイトル PATCH には revision がないため、複数端末での改名は後から保存した値が優先される。08 では契約を広げず、この制約を引き継ぐ。タイトル競合検出は後続設計とする。
- 最も注意が必要なのは、本文保存・改名・GET の応答がキャッシュを上書きする境界。応答順を変えたテストを必須にする。
- 計画 06 による画面構造変更が進行中なら、最新構造へ組み込む。旧版の `PageDocument` を前提に作り直さない。
- セッション変更時の mutation 応答の無効化方法は、着手時点の認証・キャッシュ管理に合わせて決める。ユーザー ID だけで同一ユーザーのログアウト・再ログインを区別できない場合は、セッション世代等の既存境界を確認する。
- 08 完了だけでは段階 1 全体の完了とはしない。自動保存とスラッシュメニューは、それぞれ計画 06・07 の受け入れ基準で判定する。
