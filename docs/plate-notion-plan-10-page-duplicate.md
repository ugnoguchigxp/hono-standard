状態: 未実装。2026-09-30 に設計書のみ作成。

依存: [01](./plate-notion-plan-01-pages-api.md) のページ・所有者モデル、[02](./plate-notion-plan-02-sidebar.md) の一覧と作成後の導線、[04](./plate-notion-plan-04-content-api.md) の本文検証、[05](./plate-notion-plan-05-editor-save.md)・[06](./plate-notion-plan-06-autosave.md) の保存保護、[08](./plate-notion-plan-08-title-edit.md) のタイトル状態合算。[09](./plate-notion-plan-09-page-move.md) と階層・操作中の保護を整合させる。09 の設計書完成と09の実装完了は別であり、移動APIそのものは複製の必須依存ではない。

## 目的と選定理由

保存済みページのタイトルと本文をコピーし、独立した新しいページとして編集できるようにする。09で扱う移動に続いて、全体コンセプトの段階2「ページ移動・複製・ゴミ箱」の複製を具体化する。既存ページと本文を利用でき、検索・添付・共有・データベースを導入せずに再利用の体験を作れる。

子孫の複製は、新旧ページIDの対応、内部リンクの置換、件数制限等を必要とするため独立した後続範囲とする。10が全体構想の最後という意味ではない。要件対応と不足は [対応表](./plate-notion-requirements-coverage.md) に整理する。

## 範囲と非目標

現在選択中の本人の未削除ページ1件と、その保存済み本文を複製する。新ページの親は複製元と同じ。複製元・子孫・他ページのデータは変えない。

子孫の複製、未保存下書きのコピー、複製先の選択、ドラッグ、別ユーザーへのコピー、テンプレート登録、メディア・DB行・リンクのコピー規則、削除・ゴミ箱、AIは対象外。作成後の場所変更は09の通常移動を使う。

## UI 契約

1. 選択中ページに対する「ページを複製」ボタンをサイドバーへ置く。未選択、詳細・一覧取得失敗、タイトルまたは本文の未保存・保存失敗・競合・送信中、移動等の別操作中は無効にする。
2. 確認ダイアログに複製元タイトルと「このページのタイトルと保存済み本文を複製します。子ページは含みません」を表示する。「複製する」「キャンセル」を用意する。
3. ダイアログを開いた時点の title / parentId / content.revision を固定する。ダイアログ中は元ページの編集を一時無効にし、送信直前にも保存状態を確認する。下書きを破棄・強制保存しない。
4. 同じ親に、元タイトル末尾へ「 のコピー」を付けた新ページを作る。200文字上限に収まるよう元タイトルを短くする。共有タイトルスキーマと同じ文字数基準で検証し、サロゲートペアを途中で切らない。空の元タイトルは既存契約上存在しない。
5. 同名タイトルは許容する。「コピー2」などの連番や一意制約は導入しない。サイドバーの既存同名識別を利用する。作成日時順で表示し、元ページの直後へ挿入する約束はしない。
6. 送信中は二重送信・キャンセル・ページ切替・作成・改名・移動・ログアウトを保護する。標準のbeforeunload確認も対象にする。ダイアログを閉じるだけで進行中リクエストを取り消したことにしない。
7. 成功後は一覧を更新し、新ページの親・祖先を展開して新IDの `/pages/$pageId` を開く。POST応答を理由に空本文を仮表示しない。新ページGETで保存本文を取得してエディタを作る。
8. 複製成功後の一覧取得・画面移動が失敗したら、「複製しました」と新ページを開く手段を残す。再取得・再移動は複製POSTを再送しない。

ダイアログはラベル・見出し・aria-modal・フォーカス保持・送信前Escape・起動ボタンへのフォーカス復帰を実装する。状態はセッション世代と元pageIdに紐付け、送信前に対象が変わったら閉じる。

## API 契約と競合検出

`POST /api/pages/:id/duplicate` を既存認証配下へ追加する。所有者は認証コンテキストから取得する。入力は両端で共有する strict schema とする。

```json
{
  "requestId": "123e4567-e89b-42d3-a456-426614174000",
  "expectedContentRevision": 3,
  "expectedTitle": "会議メモ",
  "expectedParentId": null
}
```

全フィールド必須。requestIdはUUID、revisionは0以上の安全整数、タイトルは共有タイトルschema、親はUUIDまたはnull。任意のコピー本文・ownerId・targetId・新タイトル等は受け付けない。期待値は利用者が確認した保存済み状態。サーバー側で本文を読み取る。

| 条件 | 応答 |
| --- | --- |
| 初回成功 | `201 { "page": Page }`。既存 createPageResponseSchema を再利用 |
| 同じ操作の再送 | `200 { "page": Page }`。同じ複製先IDを返し、新規作成しない |
| 未ログイン・入力不正 | 既存方式の401 / 400 |
| 新規操作で複製元が他人・不存在・削除済み、親が利用不可 | 同じ404 `{ "message": "Not found" }` |
| 元本文revision・タイトル・親の不一致 | `409 { "message": "Source page changed", "code": "SOURCE_PAGE_CHANGED" }` |
| requestIdを違う元ページまたは入力で再利用 | `409 { "message": "Duplicate request conflict", "code": "DUPLICATE_REQUEST_CONFLICT" }` |
| 同じ操作の複製先が削除済み | `409 { "message": "Duplicated page unavailable", "code": "DUPLICATED_PAGE_UNAVAILABLE" }`。再作成しない |
| 元の保存本文が不正、DB破損、書込み失敗 | 500。新ページ・本文・操作記録は残さない |

同じ操作の再送では複製先の現在の Page を返す。作成後に改名・移動されていても同じIDを返し、最初の本文を再上書きしない。応答バイト列の完全一致ではなく、複製先IDと作成回数の一致を保証する。

expected値の照合は最初の作成だけで行う。成功済み操作の再送時に元が更新・削除されても、自分の操作記録と複製先の所有を確認して既存結果を返す。他ユーザーのrequestIdにはアクセスできない。requestIdは認可の代わりにしない。

タイトル・親は値比較のため変更後に元へ戻った履歴は検出しない。本文revisionの一致とトランザクション内の同時点の保存状態を保証し、完全な履歴競合検出は対象外。

## 再送の安全性とデータモデル

通信失敗後に同じ操作を再試行しても複製が増えないよう、DBに `page_duplicate_requests` を追加する。プロセスメモリのMapだけでは再起動・別プロセスで保証できないため使用しない。

| 列 | 契約 |
| --- | --- |
| owner_id | users.id参照、必須 |
| request_id | UUID、必須。owner_idとの複合unique index |
| source_page_id | 元UUIDの記録、必須。将来の元ページ完全削除後も再送を識別できるよう元pagesへのFKは付けない |
| input_json | 検証・正規化済み期待値を固定キー順で保存、必須。生JSONのキー順で同一性を判定しない |
| created_page_id | pages.id参照、必須。完全削除はRESTRICT |
| created_at | 必須、既存timestamp方式 |

操作記録と新ページ・本文を同一トランザクションで保存する。現在は記録を期限切れ削除しない。期限を設けると同じrequestIdから新ページが再作成されるため、保持方針変更は後続設計とする。ゴミ箱の論理削除はFKを壊さない。完全削除・ユーザー退会の際の操作記録処理は、その計画で決める。

実装時にDrizzle schemaと新migrationを生成する。既存SQL・snapshotは編集せず、番号は着手時の最新journalから採番する。今回の設計作成では生成・適用しない。

## サービスのトランザクション

`duplicatePage(ownerId, sourceId, input)` を既存サービスへ追加し、`client.write.execute()` 内で以下を一つのトランザクションとして実行する。

1. ownerId/requestIdの既存操作を確認する。元ID・正規化済み入力が違えば409。合致すれば複製先の本人所有・未削除を確認し、200用の結果を返す。記録の参照破損は500。
2. 新規操作なら本人の未削除元ページとpage_contentsを読む。親がnull以外なら本人の未削除親を確認する。祖先の循環・欠落・別所有者等は整合性エラーとして500にし、新しい孤立階層を作らない。09の祖先検証が既にあれば再利用する。
3. title、parentId、revisionを入力と照合する。不一致なら409で書込みなし。
4. 保存JSONを共有schemaと既存の本文サイズ制限で検証する。未知ノード・一時slashInput・不正JSONを黙って削除・空本文化しない。
5. 本文を深いコピーとし、新しい各ブロックには元と異なる10文字のIDを生成する。元にidがなくても付与する。既存許可の文字集合を満たす安全な乱数を使い、新依存は不要。元の全IDと新本文内のID集合を照合して衝突を再生成する。文字・bold/italic・ブロック種類と順序は維持する。変換後もschemaと1MiB上限を検証する。
6. 新UUID、同じownerId・parentId、「 のコピー」タイトル、現在時刻、deletedAt=nullでpagesを挿入する。本文はコピーJSON、revision=0、現在時刻でpage_contentsへ挿入する。元revisionを継承しない。
7. 操作記録を挿入し、作成Pageと初回/再送の判別を返す。途中失敗は三者ともロールバック。同じキーの競合は現在のwriter・DBトランザクション方式に合わせて既存記録を確認し、二重作成を残さない。

コピー後の本文にブロックID分のバイト増加があるため、元が上限以内でもコピーが上限超過する場合は `413 { "message": "Duplicated content exceeds limit" }` で書き込まない。作成後の最初の本文保存はrevision=0を送って通常どおり1へ進む。

## クライアント・キャッシュ・失敗時

`web/src/api.ts` に duplicatePage関数とmutationを追加する。codeを共有スキーマで検証して409を分類し、message文字列で分岐しない。自動retryは無効。

利用者が「複製する」を初めて押した時にrequestIdを一度生成し、送信中・通信失敗・手動再試行では同じIDと期待値を使う。明確なSOURCE_PAGE_CHANGEDの後、最新データを再取得して利用者が新しい複製を確認した場合は新requestIdを生成する。

| 状況 | 表示と操作 |
| --- | --- |
| 通信失敗・500 | 元画面と操作入力を保持。「再試行」で同じrequestIdを送る。自動再送なし |
| SOURCE_PAGE_CHANGED | 「元のページが更新されています」。明示再取得→新しい内容確認→新しい操作として複製。サーバー値で自動再送しない |
| DUPLICATE_REQUEST_CONFLICT | 操作の不整合を表示。自動でキーを変えて再送しない |
| DUPLICATED_PAGE_UNAVAILABLE | 既存コピーが利用不可と表示。新規コピーを必要とする場合は利用者が明示して別操作を開始 |
| 404 / 413 | 存在・容量のエラーを表示。内容を短縮・空本文化して成功させない |
| 401 | 既存認証処理。旧セッションのキャッシュ復活を防ぐ |

一覧query `['pages', userId, 'list']` をinvalidateする。元詳細をコピー応答で上書きしない。新詳細はGETで取得し、空contentや旧revisionを合成しない。新ページへの遷移は操作を開始した同じセッション・同じ元画面にいる場合だけ行う。セッション世代の境界は08/09の最新実装を再利用する。

保存・離脱保護は一つの集約箇所で `saving = bodySaving || titleSaving || movePending || duplicatePending` とする。本文のタイマー判定にはbody固有の状態を使う。成功後の遷移はduplicatePendingの保護を解除してから行い、未保存状態が新たにあれば既存離脱確認を通す。

## 必須テストと受け入れ基準

| ケース | 合格条件 |
| --- | --- |
| ルート/子ページを複製 | 新ID・同じ親・コピータイトル・本文一致。元と子孫は不変 |
| 装飾・見出し・空本文 | 同じ表示内容。新ブロックIDは元と異なり、コピー内で一意 |
| 200文字タイトル | suffix込みで共有検証を通り、文字を壊さない |
| コピーを編集保存 | 元本文不変、コピーrevisionは0→1、再読み込み後も独立 |
| 別ユーザー/削除済み/未ログイン | 404/401、新ページ・本文・操作記録なし |
| 不正入力・保存JSON・一時ノード | 拒否、データを黙って捨てない |
| 変換後1MiB超過 | 413、孤立レコードなし |
| 元本文・改名・移動との競合 | 409、トランザクション内の整合したコピーだけを作る |
| 同じrequestIdの並行/再起動後再送 | 作成は1件、同じコピーID。初回201、再送200 |
| requestIdの入力違い/別所有者 | 入力違い409、他所有者の記録・コピーを漏らさない |
| 応答紛失後の再試行 | 同じキーでコピーが増えず、作成済み先へ進める |
| コピーが後で改名・移動/削除 | 再送で再作成・本文上書きしない。削除時は利用不可409 |
| 本文/操作記録の挿入失敗 | 全体ロールバック。元ページ不変 |
| 未保存・失敗・競合状態 | 複製開始不可、下書きを保持 |
| 成功後一覧/遷移だけ失敗 | 成功を保持、GET/遷移再試行でPOSTを増やさない |
| 遅延応答・ユーザー切替 | 旧キャッシュ・画面遷移が新セッションへ混ざらない |

実DB統合テストは既存の一時SQLite・実migration・Hono app.request方式に合わせる。pages/page_contents/操作記録の件数・内容を確認する。再起動相当はDBを保持し別service/runtimeで再送する。UIはTesting Libraryと遅延Promiseで検証し、実時間sleepを使わない。
